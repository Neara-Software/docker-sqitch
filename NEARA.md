# Neara releases

Push to `neara-release`, or run **Neara ECR release** manually on that branch,
to build the root Sqitch image for Linux amd64 and arm64 and publish to the
CICD account in `ap-southeast-2`. The workflow smoke-tests Sqitch and its
PostgreSQL driver before publishing. Upstream Docker Hub jobs are skipped
in the Neara fork.

The same workflow runs on `main` at 10:00 UTC on the 25th of each month.
Its `rebuild` job dispatches itself on `neara-release`, where the `publish` job
builds and pushes using that branch's OIDC identity. The dispatch job needs only
Actions write permission. Running the workflow manually on `main` also dispatches
a release build; running it on `neara-release` builds directly.

Both release builds pull the current Debian base and rebuild every layer without
cache, refreshing APT and CPAN dependencies. Sqitch stays at the version selected
in `.envrc`; updating that version is a separate change. Each rebuild publishes
a new immutable image. Consumers adopt its tag or digest in a subsequent release.

Each image has a tag of the form
`v1.6.1-<full-commit-sha>-r<github-run-id>.<attempt>` and OCI version/source/revision
labels. The version comes from `.envrc`. Run IDs and attempts make tags unique
because CICD ECR repositories have immutable tags. The published tag and digest
appear in the workflow summary; use the digest to pin deployments.

## Required setup

Infra already defines the Sqitch repository in
`pulumi/projects/aws-cicd/Pulumi.ap-southeast-2__prod.yaml` under `neara/sqitch`,
with replication and a 60-day image expiration policy. Its physical repository
name is generated by Pulumi: do not assume it is literally `neara/sqitch`.

The checked-in infra currently has no GitHub Actions push role for this repository.
In that repository entry, configure `github-actions-push-repo` as
`Neara-Software/docker-sqitch` and `github-actions-push-subject` to match this
repository's OIDC subject. Follow the adjacent GitHub Actions repository entries
if the organization uses immutable organization/repository IDs in its subjects.
Restrict the trust to `neara-release` where the subject format permits it.
Have the infra deployment process provision this configuration.

Set these GitHub repository **Actions variables** from the deployed
`organization/aws-cicd/ap-southeast-2__prod` stack outputs:

- `CICD_ECR_ROLE_ARN`: the Sqitch push role ARN from `aws_github_actions_ecr`
  (role name convention: `github-actions-ecr-push-Neara-Software-docker-sqitch`).
- `CICD_ECR_REPOSITORY`: the physical repository name from `ecr_neara/sqitch`.

Authentication uses GitHub OIDC; AWS access-key secrets are unnecessary.
The workflow reports missing variables before building.

Keep `.github/workflows/neara-release.yml` on both the default branch, `main`,
and `neara-release`. GitHub runs the schedule from `main`; the dispatched build
runs from `neara-release` to match the ECR role's branch trust.
